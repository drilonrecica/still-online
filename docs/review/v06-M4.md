# v0.6 M4 — release-ready gate

The last gate before v0.6.0. It played four whole days, each the way a player would and each on a different device:

- **Phone, portrait (412×915):** day 1 as a girl in English.
- **Phone, landscape (915×412):** day 6 as a boy in German.
- **Tablet (1024×768):** day 10 as a girl in English.
- **Desktop (1280×800):** day 6 as a girl in English, as a regression check against `docs/review/v05-W4/`.

It applied the gate procedure and the touch rubric, and reports the bundle sizes against v0.5. Nothing was tagged, pushed or released.

## What v0.6 built

- **M0:** the device class (`phone` / `tablet` / `desktop` on `.desktop-root[data-device]`), the work area from `visualViewport`, and the touch primitives (`useLongPress`, `useActivate`). It also added the `phone`, `phone-landscape` and `tablet` Playwright projects.
- **M1:** the touch shell. On a phone, windows render maximized without writing that to the store. The taskbar is 40 px, tablets get 36 px title bars and 16 px grips, and the Start menu, tray, toasts, Stapley and dialogs are sized for fingers.
- **M2:** every app on touch. Messenger, Mail, the folders, the system apps, Notepad and TuneMole. Web Explorer gets Fit to screen / Actual size. Paint, Snapshot Booth and Amplifier also work by touch.
- **M3:** the four games on touch (`ScaleToFit`), the Konami swipe, Fluff by touch, and the phone playthrough.
- **M4-01:** the release e2e flows, the README section, `docs/architecture-v0.6.md` and `docs/release-notes-v0.6.0.md`.

## How to try it

`npm run dev`, then open `http://localhost:5173/still-online/?speed=fast` (the fast clock makes chats, dialing and downloads quick). Use Chrome DevTools device mode: Pixel 7, rotate for landscape, or a 1024×768 touch tablet. On a real phone, run `npm run dev -- --host` and open the network URL it prints, on the same Wi-Fi.

Run this gate's review per device:

```sh
npx playwright test v06-review-m4 --grep @review --project phone            # day 1, EN, girl
npx playwright test v06-review-m4 --grep @review --project phone-landscape  # day 6, DE, boy
npx playwright test v06-review-m4 --grep @review --project tablet           # day 10, EN, girl
npx playwright test v06-review-m4 --grep @review --project chromium         # desktop, day 6
```

`tests/e2e/v06-review-m4.spec.ts` seeds each story day with only that day's chats left (`seedStoryDay`), checks the day on the boot screen, logs on by touch, and plays every friend who writes that day to the end. Along the way it:

- measures a sample of tap targets (the Start button 40 px; on a phone, the Send and title-bar Close buttons 36 px; tablet title bars 36 px)
- emulates the on-screen keyboard by shrinking the viewport while Notepad is focused, and checks the text box stays above it
- rotates mid-use (a chat on a phone, four floating windows on the tablet) and checks the window stays usable
- lists every visible control under 36 px per phone shot as a `small-targets.json` attachment
- fails on any console or page error, or any sideways page scroll

All four runs pass.

## Fixes made in this gate

All are scoped to `[data-device='phone']` / `[data-device='tablet']` or are layout-neutral on the desktop. The desktop regression and every desktop e2e spec are unchanged.

- **Landscape login:** in a landscape phone the login column is 4 px taller than its box. The flex column squeezed the account tile (the Log On button) to xp.css's 23 px button minimum, while its 48 px picture spilled out, so the real tap zone was 23 px tall. On a phone the login column's items no longer shrink, and the column scrolls instead.
- **A chat lost its place when rotated:** portrait to landscape halves the transcript's height and kept the old scroll offset, so the newest lines fell below the fold. The transcript now stays on the newest line when it is resized, as it already did for new lines and language switches, but only if the player was already at the bottom. This also helps when the on-screen keyboard shrinks the window.
- **Tablet tray:** its icon buttons kept xp.css's 75 px button minimum, so the tray was 443 px wide. A portrait tablet showed only two of four window buttons. They are now 40×40, and the tray is 303 px. The language badge keeps its 18 px box, as on a phone.
- **The active window's taskbar button scrolled away on rotation:** the touch taskbar's sideways-scrolling row kept the front window's button in view only when the front window or the window count changed. A rotation narrowed the row without either. It now does it on a resize too.
- **New tests:**
  - `Transcript.test.tsx` (resize, and keeping the place when scrolled up)
  - two `v06-m4.spec.ts` tests in the default suite: a phone login-tile-plus-rotation test, and a tablet tray test that opens four windows and rotates to portrait
  - this gate's `v06-review-m4.spec.ts`
- Each fix's e2e test was seen failing on the code before it (23 px tile; newest line out of view after rotating; the active taskbar button 24 % visible).

Logged in `docs/decisions.md` (M4-G).

## Known gaps and follow-ups

None blocks the release.

- **Wide windows on a portrait tablet:** rotation re-clamps windows by position only (`clampPosition`, as the design spec says). An 800 px Web Explorer runs 32 px past a 768 px screen, with its Close button off the edge. Its title bar, Maximize button and taskbar button stay in reach. A later version could shrink windows that are wider than the work area.
- **Tablet taskbar overflow:** with more labelled window buttons than fit (four in portrait), the row scrolls sideways by finger without a scrollbar (the M1 design). The front window's button is always in view, but nothing shows that more are hidden. XP's button grouping would show it better.
- **Landscape Start menu:** the pinned list is cut by „Alle Programme" mid-item. It scrolls (M1's capped menu), but nothing else says so.
- **Site links at Fit to screen** are small targets on a phone (the M2-02 design; Actual size is the fix for a player).
- **Still open from M2 and M3:**
  - Mines' small cells where the field can't fit 36 px (Expert on a phone, Beginner in landscape)
  - the portrait letterbox in Hen Hunt and Pinball
  - Notepad's menu widths, Mail's column header, Regional's tab and tablet dialog buttons
  - the phone tray badge touching its border in landscape
- **Not done here, by the plan:** no tag, push or release. The owner pushes and tags `v0.6.0`.
