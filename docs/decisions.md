- M0-01: `App` renders `data-device` from `useDevice()` as a JSX attribute, instead of `installDevice` writing `dataset.device`, so React owns the attribute. `installDevice` skips the re-clamp while the device is a phone: `reclampAll` caps stored `w`/`h`, and the touch rules say stored geometry must survive a trip from desktop to phone and back (phone windows render maximized anyway). `device.ts` imports the windows store and `windows.ts` imports `getDevice`/`taskbarHeight`. That is a cycle, but it is safe because neither module calls the other while it loads. A swipe over the shell ends in `pointercancel` (browser pan under `touch-action: manipulation`), and the smoke spec asserts that (docs/touch.md).
- M0-02: `useActivate` and `useLongPress` return a binder (`press(arg)` → handlers) instead of plain handlers, because most sites are lists and a hook can't run inside `.map()`; gesture state is shared per list, which is safe because one finger gestures at a time. `onActivate` also gets `(via, target)` so title bars can skip their buttons and a phone can ignore a double-tap maximize. The click that ends a long-press is swallowed by a native capture listener on the pressed element (React handles `onClick` at the root, so it never sees it). A single tap opens, and a second tap within 400 ms is ignored so a habitual double-tap doesn't open two windows; title bars use `touchTaps: 2`. A nested long-press claims the native pointerdown, so an ancestor's long-press doesn't fire too. The Amplifier track menu also opens on a mouse right-click, the desktop counterpart of the long-press. On touch, a tap opens a folder item, so selecting one to rename or delete without opening it has no touch path yet.
