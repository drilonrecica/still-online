# Internationalization (v0.3)

still online runs in **English (`en`)** and **German (`de`)**. No i18n library is used. The system is a small set of typed catalogs, `t()`/`useT()`, `Intl` formatting and language-neutral persisted state. This doc is binding for every v0.3 task. The baseline is "i18n rules" in `tasks.md`.

```
src/i18n/
  types.ts         Locale, LOCALES, Messages, MessageKey, MessageArgs, TFunction, TextRef   (P0-01)
  messages/en.ts   source of truth, nested `as const`                                       (P0-01: `common` only)
  messages/de.ts   `export const de: Messages = {…}`                                         (P0-01: `common` only)
  detect.ts        detectLocale(languages), detectBrowserLocale()                           (P0-02)
  t.ts             t(key, …args), getLocale(), translate(locale, key, …args), MESSAGES      (P0-02)
  useT.ts          useT(), useLocale()                                                      (P0-02)
  format.ts        formatTime / formatLongDate / formatShortDate / formatDateTime /
                   formatNumber / formatRelativeDay                                         (P0-03)
src/content/de/    German content, same ids as src/content/                                 (P0-06, P2)
```

## Catalogs

- `en.ts` is one nested object, `as const`, with **one top-level key per area** (`common`, `boot`, `login`, `desktop`, `taskbar`, `startMenu`, `wm`, `fs`, `apps`, `messenger`, `mail`, `regional`, `sites.<host>`, … as listed in `tasks.md`). Leaves are strings or functions.
- **String values** use `{param}` tokens: `'{name} says:'`. Because `en` is `as const`, the token names are part of the type (`TemplateParams`), so `t('messenger.says', { name })` must pass exactly those params.
- **Function values** are for grammar a template can't express: `files: (p: { n: number }) => (p.n === 1 ? '1 file' : `${p.n} files`)`. `t` passes the params object through. German must provide a function with the same params.
- **`MessageKey`** is the union of every leaf dot path of `typeof en` (`CatalogKey`). **`Messages`** is `typeof en` with string literals widened to `string` (`CatalogShape`). `de.ts` is annotated `Messages`, so a missing or extra key, or a wrong function signature, fails `tsc`.
- **`MessageArgs<K>`** is the rest tuple `t` takes: `[]` for plain strings, `[params]` for templates and functions. `TFunction = <K extends MessageKey>(key: K, ...args: MessageArgs<K>) => string`.
- Numbers in params are formatted by the caller (`formatNumber`) before `t` sees them, unless a function value formats them itself. `t` never guesses a locale format.
- **Parity** (`src/i18n/catalog.test.ts`, P0-02): `en` and `de` have the same key sets; each German string uses the same `{params}` as the English one; every function value runs with a sample params object in both catalogs.
- A missing param leaves the `{token}` visible. That is an authoring bug, and parity keeps it out of the catalog.
- **Adding a third language** takes three steps. Add it to `LOCALES`, `LOCALE_NAMES` and `INTL_LOCALES`. Write `messages/<xx>.ts: Messages`. Add `src/content/<xx>/`. Nothing else switches on `'de'` by name, except content accessors and the per-locale lint list.

## Locale state, detection, live switching

- **`settings.language: Locale | null`** is persisted. `null` means not chosen yet. On the very first start (and until the player chooses) the effective locale is `detectLocale(navigator.languages ?? [navigator.language])`. It walks the list in order and the **first supported** primary subtag wins: `['fr','de-DE']` → `'de'`, `['en-GB','de']` → `'en'`. With no `de`/`en` entry, or an empty list, it returns `'en'`. Unknown persisted values sanitize to `null`.
- **Read the locale only through `getLocale()`** (plain TS) **or `useLocale()`** (React). Never read `settings.language` directly. `setLanguage(l)` writes it.
- **`t(key, …args)`** reads `getLocale()` on every call, so it never caches text. `translate(locale, key, …args)` is the same for an explicit locale. A key missing from a locale falls back to English, then to the key itself; `t` never throws. **`useT()`** subscribes to the settings store's `language` and returns a `TFunction`, so components that call it re-render on a switch.
- **Live switching never reloads.** React views re-render through `useT`/`useLocale`. Non-React code that caches rendered text (indexes, schedulers, canvas buffers) subscribes with `useSettingsStore.subscribe` and rebuilds when the locale changes. Examples: the Searchly index (per locale), canvas text in games (redraw), and the screensaver marquee.
- `App.tsx` keeps `document.documentElement.lang` equal to the locale, like the `data-theme` sync. `index.html` keeps `lang="en"` until hydration.
- **Where the player switches** (P0-07):
  - The login screen dropdown "Language / Sprache", visible on every visit before logging on.
  - The `regional` app ("Regional and Language Options" / „Regions- und Sprachoptionen"), in System Tools, with OK/Cancel/Apply.
  - The `EN`/`DE` tray badge left of the network icon, which opens a two-item menu.
  - All three call `setLanguage`. Language names always show in their own language ("English", "Deutsch").
- **Tests:** `src/test/setup.ts` pins `language: 'en'` before each unit test. German tests set `useSettingsStore.setState({ language: 'de' })` themselves. Playwright's default project runs `locale: 'en-US'`; German specs use `test.use({ locale: 'de-DE' })`.

## Dates and numbers

Everything goes through `src/i18n/format.ts`, which uses `Intl` with `INTL_LOCALES` (`en-US`, `de-DE`) and caches one formatter per locale. "Now" is always `now()` from `src/os/clock.ts`. German output looks like `15:07`, `Sonntag, 14. Oktober 2007`, `14.10.2007` and `1.234`. Relative days use `formatRelativeDay(n, locale)` (`today`/`heute`, `yesterday`/`gestern`, `N days ago`/`vor N Tagen`). No `toLocaleString('en-US')` and no hand-built month names.

## Persisted state: ids and params, never generated text

**Rule:** saved state holds ids, references and raw params. Text is rendered at view time in the current locale. Only text the **player typed** is stored as text. Each store migrates its v0.2 shape **inside its own `sanitize`**: `STORAGE_VERSION` stays 1, keys stay `still-online:v1:*`, and no save is wiped. Every migration has a test that loads a JSON fixture of the v0.2 shape.

Generic references use `TextRef = { key: MessageKey; params?: TextParams }`. `TextParams` values are strings or numbers. `sanitize` drops a ref whose key isn't in `en.ts` (`isMessageKey`, `sanitizeTextParams` in `src/i18n/refs.ts`) and falls back to the default text. `translateRef(locale, key, params)` renders a stored ref.

`src/test/fixtures/v02-save.json` is a v0.2 save (settings, windows, fs, mail, web) written by the v0.2 code. `src/test/v02-migration.test.ts` loads it and checks that nothing the player made is lost, that the English renders exactly as before, and that the re-saved shape has no generated English. P0-05 and the e2e migration spec reuse it.

### `windows` (P0-04)

- `WindowState.title` is **no longer persisted**. The title is `t(app.titleKey)`, because the registry gets `titleKey: MessageKey` (and `labelKey?`) instead of `title`/`label` strings.
- Windows whose title changes at runtime store `titleKey` + `titleParams`, set with `setWindowTitle(id, key, params)`. Examples: chat „<name> - Unterhaltung", „<file> - Editor", „<file> - Paint", the Explorer folder name, Mail, and the Web Explorer page title.
- Params are names the title shows: a file name the player chose, a contact's display name, a folder or page name. The app that set them **sets them again when the locale changes** (its effect depends on `useLocale()`), so a localized name inside a param refreshes while the window is open. After a reload the stored params show until the app mounts.
- **Migration:** the v0.2 `title` is ignored and the window renders from `titleKey`. The app's first effect restores the dynamic part.
- Rendering: `renderWindowTitle(win, app, locale)` (`src/os/wm/title.ts`), used by the titlebar and the taskbar. `setWindowTitle` is type-checked like `t`: `setWindowTitle(id, 'notepad.title', { file })`. Titles avoid localized text in params where a key can say it (`apps.notepad.title`, `notepad.untitledModified`, `fs.folders.<id>`); Mail (folder name) and Web Explorer ("Cannot find server") put localized text in a param and re-set it from an effect that depends on `t`.

### `fs` (P0-04)

- **System folders** (`root`, `docs`, `pics`, `music`, `recycle`) are persisted without `name` (`SystemFolderRecord`) and render from `fs.folders.<id>`.
- **`seed:` nodes** (`SeedNodeRecord`) keep `id`, `parentId`, `type`, times, `photo` minus `caption`, `trackId`, `url`, `deletedFrom` and `dirty?`. Untouched seeds take `name`, `text` and `photo.caption` from `getSeedFiles(locale)` by id. **Rename or edit** sets `dirty: true` and freezes all three as rendered at that moment. From then on the file is the player's and stays in that language. Moving, deleting or restoring a seed does **not** make it dirty.
- **Player files** (`f:<random>`) store everything as they are today. That includes files created by a player action from generated content (saved mail attachments, TuneMole downloads, snapshots): they freeze in the language they were made in, like files on a real disk.
- `path`, `uniqueName`, sorting, search and Explorer titles all use **rendered** names.
- **Migration:** v0.2 system folder names are dropped. A v0.2 seed node whose `name`/`text`/`caption` equal the English seed gets those fields stripped. One that differs (the player renamed or edited it) becomes `dirty: true` with its text kept.
- **Implementation:** only the _saved_ shape is neutral. In memory every node is rendered (`name`/`text`/`caption` filled in), so Explorer, Notepad, Paint, the pickers, sorting and search keep reading plain `FsNode`s. `src/os/fs/records.ts` converts both ways: `partialize` saves `toRecords(nodes)`, `sanitize` rebuilds rendered nodes for the current locale, and a settings subscription in `store.ts` runs `localizeNodes` on a language switch. Seeds come from `seedFilesFor(locale)` (`src/os/fs/seeds.ts`, English for both until P0-06). `writeText`, `writeImage` and `rename` set `dirty`; so do `seed()`/`restore()` when a name clash forces a `(2)` suffix. Notepad follows its file while the buffer is unchanged, so an open untouched seed switches language too.

### `mail` (P0-04)

Messages become `MailRecord`. All variants share `{ id, folder, read, receivedAt }`.

| kind        | stored                                                   | rendered from                                                                   |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `content`   | the content id                                           | `getMailContent(locale)` by id (from, subject, body, attachments)               |
| `bounce`    | `params: { to, subject }`, both as the player typed them | `mail.bounce.*` (sender name, subject, body)                                    |
| `autoReply` | `contactId`, `again`, `params: { subject }`              | the friend's auto-reply content (first/again); „RE: <subject>" from the catalog |
| `text`      | full `from`/`to`/`subject`/`body`/`attachments`          | verbatim: player-written mail and unrecognized v0.2 mail                        |

- The player's own address and name are derived at render (`playerAddress()`). An empty subject is stored as `''` and renders `mail.noSubject`.
- In `text` records the player is stored as the marker `{ name: '', address: '' }` (`PLAYER`) and rendered as `playerAddress()`, so a default name follows the language. `bounce` stores `to: ''` for an empty recipient (renders `mail.bounce.unknownRecipient`).
- Content that isn't shipped (test fixtures passed to `deliver`) is stored as `text`, since it can't render by id.
- `src/apps/mail/records.ts` holds `sanitizeRecord`, `migrateV02` and `renderMail`/`renderMails`; Mail renders with `useLocale()` and the player name. The German reply prefix is `AW:`.
- **Migration:** an id found in the English content becomes `content`. A mail from `mailer-daemon@livemail.example` whose subject starts with `Undeliverable: ` becomes `bounce`, with `to` parsed from the body. An inbox mail from a friend's handle whose body equals that friend's English `body`/`again` becomes `autoReply`. Everything else becomes `text`, with the player's address (from the hydrated settings) turned into the marker. A subject of `(no subject)` becomes `''`. `deliveredDays` is unchanged.

### `settings` (P0-02, P0-04)

- `language: Locale | null`, default `null` (P0-02).
- `playerName`, `awayMessage` and `screensaver.text` are `string | null`. **`null` = the localized default**: `Player`/`Spieler`, `brb`/`bin gleich wieder da`, and `still online...` in both. `''` stays a real value where it is today (an empty away message).
- Saving a value that equals the current locale's default stores `null`, so it follows later switches.
- **Migration:** `'Player'` → `null`, `'brb'` → `null`, `'still online...'` → `null` (any locale's default, in fact). Anything else the player typed is kept.
- Read them only through `getPlayerName()`/`usePlayerName()`, `getAwayMessage()`/`useAwayMessage()` and `screensaverText(saver, locale)` from `src/i18n/settingsText.ts`. The defaults live in the catalog under `defaults.*`.

### `web` (P0-04)

- Favorites become `FavoriteRecord { url, title? }`. Default favorites are stored as `{ url }` and named at render from the catalog (`browser.defaultFavorites.<host>`, via `favoriteTitle`/`renderFavorites` in the web store); the site registry has no per-locale text yet. A player-added favorite keeps the `title` it was added with.
- **Migration:** a favorite whose `url` and `title` equal an English default drops `title`.
- `counters`, `votes`, `guestbook` (the player's posts) and `myProfile` (what the player saved in the editor) are player data and stay as stored.

### `messenger` (P0-05)

- **Transcripts** become `NeutralTranscriptEntry[]`:
  - `{ kind: 'line', from: 'contact', scriptId, nodeId, lineIndex, params?, at, whileAway? }` for a script line.
  - `{ kind: 'choice', from: 'player', scriptId, nodeId, choiceIndex, params?, flavor?, at }` for a picked reply. `flavor` holds the emoticon codes the player added, kept as typed.
  - `{ kind: 'awayReply', from: 'contact', at, whileAway? }`.
  - `{ kind: 'typed', from: 'player', text, at }` for free text.
  - The existing `nudge`/`wink` entries.
  - Legacy `{ kind: 'message', text }` entries, rendered **verbatim**.
- **Params** (`LineParams`) are raw: `game` id, `score` number, `trackId`. At render, `{game}` comes from the catalog (`games.<id>`), `{score}` from `formatNumber`, and `{artist}`/`{title}` from the playlist track. `{name}` is always the player's current name, so it is never stored.
- **`renderEntry(entry, contacts, locale, playerName)`** is one pure function, memoized per entry and locale. The chat transcript, Message History, toasts ("X says: …") and the typing-time calculation all use it.
- **Presence:** `ContactProgress.personalMessage` becomes a `PersonalMessageRef`. It is `'initial'`, `{ kind: 'day', day }`, `{ kind: 'line', scriptId, nodeId, lineIndex, params? }` (a `personalMessageChange`), or `{ kind: 'literal', text }`. It is rendered from the merged contact for the current locale.
- **Player:** the player's own `personalMessage` is typed text (or the `♫ artist - title` now-playing line, which has no words to translate). `player.awayMessage` follows the settings rule: `null` = the localized default.
- **Migration:** legacy `message` entries are kept. Legacy `personalMessage` strings become `{ kind: 'literal', text }`. A legacy `player.awayMessage` of `'brb'` becomes `null`.

### Contact groups (P0-04)

`Contact.group` becomes `ContactGroupId` (`friends | school | family`). The list adds `offline` (`ContactListGroupId`). Labels come from `messenger.groups.<id>`, the headers from `messenger.groups.count`/`offlineCount`. Groups aren't persisted; only content and `contactList.ts` change.

### Stores without generated text

- `notepad` holds the player's text.
- `amplifier` holds track ids and numbers.
- `world` holds days, unlock ids and times.
- `games` holds scores and names the player typed. Its one generated value, the `'Anonymous'` fallback name, becomes `''`, rendered from the catalog, with `'Anonymous'` → `''` in `sanitize`. This is done with the games strings (P1-06).

## Content per locale (P0-06, P2)

- English content stays in `src/content/**`. German lives in `src/content/de/**` with the **same ids**.
- **Accessors** (in `src/content/locale.ts`) return German for `'de'` and English otherwise: `getContacts`, `getSeedFiles`, `getMailContent`, `getProfiles`, `getSiteText(host, locale)`, `getBalloons`, `getTips` and `getTuneMoleResults`, all taking `(locale)`. Consumers call them at render time and re-render on a switch.
- **Contacts are text overlays.** `src/content/de/contacts/<id>.ts` exports a `ContactOverlay`. It contains:
  - `displayName?`: only when the name has English words.
  - `personalMessage?`, `awayReply?` and `days?` (presence messages per day key).
  - `scripts: { [scriptId]: { [nodeId]: NodeOverlay } }`, where a `NodeOverlay` is `{ lines: string[]; choices?: { text, label? }[]; personalMessages?: { [lineIndex]: string } }`.
  - `lines` has one entry per English line (`''` for a line without `text`). `personalMessages` translates the `personalMessageChange` of the line at that index.
  - Delays, triggers, nudges, winks, status changes, unlocks and the node graph always come from English.
- **Merge** (`mergeOverlay(content, overlay)`) builds a full `ContactContent` and replaces only text. Missing overlay text falls back to English. That keeps the game playable before P2, and `src/content/fallback.test.ts` (P2-07) proves no fallback is left. A helper reports fallbacks for tests.
- **Other content** (files, mail, profiles, sites, balloons, tips, TuneMole) is a full German module of the same type, keyed by the same ids, or the same array order where items have no id. P0-06 creates these as re-exports of English marked `// TODO(P2)`.
- **Structural parity** (`src/content/parity.test.ts`) is mandatory. Every overlay script and node exists in English. `lines.length` and `choices.length` match. `personalMessages` keys point at English lines with a `personalMessageChange`. Placeholder tokens match per line and choice. Other content has the same ids or lengths. Localize _inside_ a line; never add or remove one. This is what lets old transcripts re-render in the other language.
- **Lint per locale** (`lintText(text, locale)`): the shared rules apply (`.example` only; no real TLDs, including `.de`/`.at`/`.ch`; no brands). German adds the anachronism list from P0-06.
